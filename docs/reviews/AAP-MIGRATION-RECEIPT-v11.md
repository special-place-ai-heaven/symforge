# AAP migration receipt — Feature 020 V11 (T049)

**Status: pre-activation. This receipt does NOT claim the V11 exports are
live.** `symforge::embed::*` does not carry the introduced V11 atoms and
`symforge::server_api` is `pub(crate)`; every observation below was made
against the DARK Slice 3 boundary through harness scaffolding, and the
machine artifact records `"claims_v11_exports_live": false`.

Generated by `execution/aap_migration_receipt_v11.py` (`--stage full`), which
materializes the frozen consumer corpus
(`tests/fixtures/public-api-v11-consumer/`, read-only) into throwaway crates
under the session scratchpad and runs one `cargo check` per atomic case. The
observations in this document are from the run against the T049 working tree
over `34952e1c` (the tree this receipt lands with); re-run the command against
the landed commit to re-bind any number here.

## Environment

- `CC=CXX=clang-cl` was pinned for every harness compile, and the receipt
  records why as a finding in its own right: **a cold build of this repository
  currently fails under the default Windows toolchain.** MSVC `cl.exe`
  14.51.36231 rejects tree-sitter-scss's GCC-style `-Wno-unused-parameter`
  (`invalid numeric argument`), and the repo's own gates only pass because
  every checkout's `target/` still carries a warm scanner object. Any
  `cargo clean` on this machine makes the repo unbuildable until the
  toolchain question is settled. This is a latent repo hazard independent of
  Feature 020.
- Case crates live in two cargo workspaces (embed vector; server-embed
  vector) with separate target directories, so feature sets never share an
  artifact tree.

**Result: the dependent-positive crate COMPILES against the dark adapter** —
all 27 embed items, all 34 inherent members, the trait edges, and the

That claim is proven non-vacuous the hard way:

- The first materialization omitted the fixture's `embed` feature, so

  vacuity; with the feature honest the same mutant fails `E0599` on exactly
  the removed method, and the restored tree compiles.

  dark tree, both the T043 failure class:
  1. `ServerExit` carried an invented `Clean` variant; the frozen contract

  2. `ReceiptWaitError` omitted the contract's `DeadlineElapsed` variant.

## The wrap-list discharge (what T049 changed in the dark tree)

All nine `wrap-planned-t049` obligations in `public_api::wrap_table()` are
discharged to `wrapped-here`, and the checked-in export delta was regenerated
through its write-then-verify opt-in (nine obligation flips, nothing else):

`AtomicAuthority`→`EmbedAtomicAuthority`, `Claim`→`EmbedClaim<T>`,

unwind-opt-out), `ShutdownReceipt`→`EmbedShutdownReceipt` (contract
`wait(Instant)` reporting observed zeros), `ShutdownReport` and
`SourceCloseReport` (contract field-for-field records).

Additionally, all contract-pinned and fixture-forced shapes now hold:

- `OperationKind`/`RetryAdvice`/`SourceRefusalKind` are made NAMEABLE via
  `pub use` in `public_api` (the compiler named them E0603 in the observed
  RED run); `lifecycle_identity` stays `pub(crate)` and censusless.
- The five handle types (`EmbeddedSourceHandle`, `ProcessRuntimeApi`,
  `EmbedRefreshTicket`, `EmbedShutdownReceipt`, `SourceCloseReceipt`) carry a
  `PhantomData<Box<dyn Any + Send + Sync>>` marker: `Send + Sync + Unpin`
  positive, `UnwindSafe`/`RefUnwindSafe` negative, as the contract's
  auto-trait matrix pins. The ten adapter-lane unwind cases prove it.
- `SourceCloseReceipt::wait(Instant)` (self-wait guard included) and
  `EmbeddedSourceHandle::search_*` returning `EmbedClaim<..>` complete the
  handle's contract shapes; `ProcessRuntimeApi` gains contract-pinned
  `Clone` + `Drop` and the `open_embedded_source`/`begin_shutdown` lanes.
- `ReceiptWaitError` gains its contract-pinned `Display` + `Error` impls.

## Divergence register (recorded, not hidden)

1. **Derive superset.** The dark wrappers carry `Debug` (and, from T048,
   `Clone`/`PartialEq`/`Eq` on the request/result/view records) beyond the
   frozen contract's CLOSED 17-entry direct-impl list. The Slice 3 oracles
   need `Debug`; the activation graph proof owns the trim decision.
2. **Refusal mapping (D18).** `open_embedded_source` maps the registration's
   `SourceAlreadyOpen` to `SelectionUnavailable` with `OnEvent` retry and the
   `evidence-absent` sentinel (no authority is examined at registration
   level). A judgment call made in the dark, reversible before activation.
3. **server_api leg.** No external crate can compile against
   `symforge::server_api` before the keyword flip — that unreachability is
   D4's design, so the server-consumer shapes are pinned by an in-crate unit
   test (`server_api::tests::dark_run_refuses_and_the_contract_shapes_hold`)
   instead of the fixture, and the fixture's `server` half stays cfg'd out.
