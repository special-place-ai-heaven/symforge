# Selecting sufficient source evidence under a token budget

**Research pilot, 25 November 2026.** The strongest local result was a difference in what a reader could establish. The existing context bundle showed the checkpoint wrapper but omitted the persistence guard it called. A single batched code-mode read of the wrapper and the right helper gave a fresh reader enough source to explain both. This demonstrates the value of finding support. It leaves open how often a selector can find it cheaply on an unfamiliar repository.

The source checkout was `79162be8`. The installed SymForge 12.1.0 code-mode server reported a ready 1,767-file index. All six symbol bodies in the two hand-selected batches matched unique contiguous ranges in the pinned Git blobs and in the working files. The experiment used existing operations and a private offline selector.

## Two live first-answer comparisons

Two source questions required reasoning across functions. One asked how `checkpoint_now` guards an existing snapshot, verifies a write and handles daemon fallback. The other asked how `get_file_content` preserves a freshness caveat, when it leaves the answer alone and what hard byte cap applies. Each arm had a fresh reader with access only to that arm's two observations. The scoring rubric was written before either reader answered. It required every critical fact to be both correct and supported. The reader could abstain.

| Question | Existing `symbol_context(bundle=True)` request + reply | Hand-selected `get_symbol(targets=[…])` request + reply | First answer against three critical facts |
|---|---:|---:|---|
| Checkpoint | 29 + 2,578 = **2,607** | 58 + 1,770 = **1,828** | Bundle **2/3**. It supported verification and fallback, but omitted the helper's manifest guard. Batch **3/3**. |
| Targeted read | 30 + 4,242 = **4,272** | 119 + 862 = **981** | Bundle **0/3**. The client received a spill preview. Batch **3/3**, including the separate 60,000-byte constant. The cap's enforcement site was outside the observation. |

Costs are `o200k_base` counts of compactly serialized code-mode tool name/arguments and returned tool envelope. Each cell was one actual code-mode request. It excludes prior target discovery, model responses, cached-input accounting and system/tool-list overhead. The bundle calls ran concurrently, and the later batch calls ran warm. These runs do not establish a latency ratio. The 1,800-token checkpoint cap in the selector trial applies to the reply only. The measured hand-selected checkpoint reply fits at 1,770 tokens even though the request plus reply totals 1,828.

The comparison deliberately gives the batched arm the correct paths and names up front. The benchmark did **not** observe automatic discovery at that cost. Checkpoint needed two bodies, `checkpoint_now` and `checkpoint_shared_index`. The wrapper itself shows what it does if `load_snapshot` fails. The targeted read used four source items in one batch: `get_file_content`, `close_targeted_read`, `fit_caveat` and `GET_FILE_CONTENT_MAX_BYTES`. The constant is independently relevant to the question. The supplied helper body does not establish a direct call edge to it. The bundle reader then chose its own recovery calls without seeing the batched arm. Two symbol searches, one batched symbol lookup and one combined source-window/guard lookup added **3,139** request-and-reply tokens across the two questions. The reader recovered the checkpoint answer and the caveat fitting behavior. It still could not establish the numeric file cap. Totals for this bounded trace were **10,018 tokens and six external requests**, with one question fully answered. The known-support comparison used **2,809 tokens and two external requests**, with both answered. These two questions, one reader per arm and the hand-supplied target locations do not provide a deployment savings rate.

**Fidelity controls.** The returned declaration line is not always the first returned source line. `fit_caveat` was reported at line 745 but its bytes began at line 742 with documentation. The hard-cap constant was reported at 552 and began at 549. Record the actual half-open byte interval and hash alongside the declaration anchor. A second negative control used a three-line, 36-byte Rust file. Default line-numbered output included display prefixes. With `show_line_numbers=False`, the reply matched all original bytes including the terminal newline. That code-mode read used **135** request-and-reply tokens. A modeled direct read with the same source and a minimal path/content envelope cost **43**. Direct reading remains a first-class option.

## Did automatic selection find the support?

**Whole-package pilot.** Five hand-assembled packages used nine distinct exact source items. The three selectors shared the same pool and the same eligibility rules. All three declined the two multi-function questions at their original budgets. The checkpoint package cost 2,277 modeled transcript tokens against a 1,800-token ceiling. It required the full `load_snapshot` wrapper even though the calling condition sufficed to answer the verification question. The targeted-read package needed four source items against a three-item cap. Raising that cap to four let all three deliver it. Four member reads are batchable in one external call. Treating each as a client round trip would misprice code mode. The small-file package fit. The lexical target rule also declined the simple numeric-cap task despite having selected the right constant. A rule can withhold too much as well as emit too much.

These were development fixtures. The four-item cap was a sensitivity test, the package membership was authored, and the reader rubric accepts alternative sources. Whether a package matches a designated gold package is an offline diagnostic. It is unavailable as a runtime sufficiency signal. The initial construction has too few feasible alternatives to distinguish good ranking from good package design.

**Support-span comparison.** A second run fixed the primary symbol for each question and offered **14 actual symbol bodies** to each selector. The pool included competing helpers, a test, and the independently relevant constant. A prechecked direct-call chain bound support to its intermediate source where available: for example, selecting `fit_caveat` as a dependency also brought in `close_targeted_read`. Other lexical hits remained eligible as independent evidence. The entire `get_file_content_noted` body overflowed the code-mode response and was excluded. This measures selection from a bounded, hand-seeded frontier. Discovering this frontier without knowing the answer remains open.

Each selector could choose up to five distinct items. Relevance used document-frequency-weighted query-word overlap. Role coverage rewarded new query terms and new syntactic roles per additional token. Facility location rewarded improved best similarity to the pool, weighted by query relevance, per additional token. All arms started with the same primary, charged shared support once and recounted the serialized JSON, including actual byte intervals and whole-file SHA-256. The answer key was used only after selection. An exhaustive subset check supplied the cheapest pack satisfying the source rubric for comparison.

| Primary reply budget | Relevance-first | Role coverage | Facility location | Cheapest sufficient subset in this pool |
|---|---:|---:|---:|---:|
| Checkpoint, 1,800 tokens | **3/3 facts**, 1,793 tokens | **2/3**, 1,550 | **3/3**, 1,793 | **1,793** |
| Targeted read, 1,200 tokens | **3/3**, 1,115 | **3/3**, 1,115 | **3/3**, 1,048 | **940** |

At the checkpoint budget, role coverage picked the unrelated file-content cap and lost the manifest guard. Both other methods chose the guard. On targeted read, facility location spent 67 fewer rendered tokens than relevance-first, but each selected an extra helper beyond the four-item sufficient set. At 400 tokens the checkpoint primary alone exceeded the budget and no method retained all three targeted-read facts. At 3,000 all three methods retained the three scored facts for both questions. The exhaustive floor applies only to this candidate pool, evidence rubric, span granularity and serialization.

**Live replay of the selected IDs.** At the primary budgets, replaying all four distinct selections through batched `get_symbol` returned unique Git- and disk-verified source spans. Relevance-first cost **1,828 + 1,157 = 2,985** actual request-and-reply projection tokens for the two questions. Facility location cost **1,828 + 1,086 = 2,914**. A fresh reader given the two live relevance-first responses answered all six scored facts and identified where the evidence stopped. These wire projections differ from the selection-budget table, because `get_symbol` returns its own schema. Neither total charges discovery or the external model's answer. The two measured questions give no reason to add facility location to the production path today.

## Where the experiment fits

SymForge already provides a strong comparator. The existing text renderer prioritizes the primary body and fits ordered optional sections under its budget. Code mode exposes the body, caller and callee references, type uses and optional definition bodies through `symbol_context(bundle=True)`. The public Rust integration also offers a structural context request and a typed claim with publication and coverage metadata. The experiment asks whether the task justifies returning a particular callee's **implementation**, guard or constant in the first answer. Replacing one set of caller rows with another would miss that question. [Section budgeting](../../../src/index_lifecycle/guidance/source.rs) · [Code-mode projection](../../../src/codemode/backend.rs) · [Rust context query](../../../src/index_lifecycle/embed_query.rs)

The design keeps three checks independent. A source slice must match admitted bytes. A relationship needs its own witness, such as an unambiguous qualified call into a definition. A useful answer must retain enough of those facts to solve the task. The first two can pass while the reader still lacks the overwrite guard. Likewise, a plausible same-name type can have perfectly valid bytes and still belong to another module. Until #2 is resolved, use only relationships that can be proved locally. An unresolved edge can be reported and expanded. Dependency-based ranking over the repository graph remains gated on resolver accuracy. [Importer controls](LEDGER.md#visible-importer-audit-for-2) · [Type dependency resolution](../../../src/live_index/context_bundle.rs)

## Why compare these selectors

LaMR separates the evidence relevant to a question from lower-similarity support needed to interpret it. PACMS selects whole items for coverage under a budget, but its relevance-only comparator retained more gold evidence at the tightest tested budget on its LongMemEval questions. A separate QA study found a tuned query-focused heuristic often matched the formal selector. These are reasons to test distinct selectors on **identical candidates**, across budgets, with both an evidence-retention check and a reader. Their numerical gains belong to their own workloads. [LaMR](https://arxiv.org/html/2605.15315v2) · [PACMS](https://arxiv.org/pdf/2606.20047v2) · [Recall Is Not Enough](https://arxiv.org/html/2607.00725v2)

For a package with required support, compare the additional value of its selected spans with the additional tokens in the rendered reply. A role-coverage rule rewards a guard or definition once. A facility-location rule scores how well the selected set represents each candidate, using its best similarity to a selected span. A rare decisive branch can lose under either rule. Use a bounded pool, take the union of exact support spans and recompute both gain and serialized cost for each remaining package. A shared helper can make another package cheaper on the next iteration. Count separators, metadata and expansion guidance, then verify the final serialized budget. These rules carry no knapsack approximation guarantee in this setting. A fit check establishes size alone.

| Finer invalidation | Start with a body-only read after an unrelated edit. Track the admitted source identity, byte range, content hash and authority of that read. Add configuration/binding or search-posting dependencies only for answers that use them. Include denial changes, moved offsets, stale generation, and identical-size replacements as negative controls. Declaration summaries that compare equal offer a separate early cutoff for semantic products. | Range and edit reuse | First try an exact subrange of a delivered span within one authorized session. Measure a fresh subagent and a compacted conversation as well as a retained base. A delta needs an exact base and a check that reconstruction yields the authorized current bytes. Charge expansion and fallback. The Rust sqz project reports 260 to 35 tokens on one repeat subrange. Its example gives a concrete comparison, and no session-wide forecast. [sqz](https://github.com/ojuschugh1/sqz) |
| Restore proof reuse under #7 | Pass the observed root, file identity, content hash, policy version and observation interval to the second verifier. Reuse only if intervening changes are reliably excluded under the host's filesystem semantics. Invalidate after overflow, watcher restart, coverage gaps or root replacement. A same-size edit within a timestamp tick must still be caught. This is a way to attack the measured 32.458 s and 15.991 s stages while preserving trust. ## Next experiment and promotion gate

Keep the existing default. Try the cheapest unresolved step first: find one missing support span after a narrow symbol read, batch it with the primary span, and compare with the user's ordinary direct read or focused code-mode script. For a known definition, conventional path and unambiguous source-witnessed call, retrieving the full callee is one option. A conditional in the caller may already settle the question. The cohort must also include ambiguous, missing, withheld and already-small targets.

1. Freeze held-out tasks, independent expected facts and acceptable alternative evidence before tuning. Include localization, explanation, repair and test generation on several repositories and languages. Compare against both a raw/direct read and a caller using the existing code-mode interface effectively. A small annotated ContextBench subset is one candidate. Keep repository, task and consuming model paired. [ContextBench](https://arxiv.org/html/2602.05892v3)
2. Discover candidates under a measured operation/time cap without a hand-supplied answer key. Record which required facts made it into the candidate pool and which survived the final rendering. Compare primary alone, primary with independently chosen support, whole-file bypass and optional section expansion. Charge code-mode serialization and all recovery. Return only a supported partial answer when the primary fits but required support is unresolved. Keep a scoped miss explicitly inconclusive on partial coverage.
3. Verify the actual bytes, authority and publication for every emitted item. Re-run with ambiguous homonyms, withheld items, changed source of the same byte length, declarations preceded by comments, overlapping spans, stale handles and a fresh or compacted client. For Rust embed, drive both first response and expansion through an external consumer, compare normalized file/range/hash, and record truncation and withholding. An opaque symbol ID and line numbering differ between APIs. [Embedded public types](../../../src/embed/parity.rs) · [Embedded symbol context](../../../src/embed/parity/symbol_context.rs)
4. Score supported answers and paired task completions, additional reads, wrong-file choices and abstentions. Record actual cold and warm wall time including candidate discovery, first answer, retries and first correct answer. At the consuming harness, separate ordinary input, cache writes/reads and output. Promote only with reproducible net savings, preserved task outcomes and evidence fidelity, and acceptable latency on code mode and embed. The prior routing trial's extra 615 tokens remains the counterexample for making a plausible policy automatic. [Read-cost gradient trial](REPORT.md#routing-trial-on-held-out-checkouts)
