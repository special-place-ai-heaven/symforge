## 1. What the last session established

### 1.1 The reporting invariant (now binding policy)

Recorded in `CLAUDE.md`:

> **A component may not report success for an operation whose completion it did
> not observe.**

This is not style advice. Six defects fixed on 2026-08-06 were one defect wearing
different clothes, and every one shipped green: a daemon reap that deleted a live
daemon's records without confirming it died; two re-parse loops that discarded a
result which can be `Skipped`/`ReadError`/`NotFound` and then asserted in a
comment that the files "were re-parsed above"; a trust envelope that collapsed to
its compact form on a *string comparison* every caller passed literally; an
`index_folder(add:true)` returning a project name no selector could resolve.

The recurring shape: **the thing that reports is not the thing that knows.**

Everything below is downstream of that sentence. When you add a status line,
banner, envelope, or success return, answer in the PR: *what did this observe,
and what does it emit when the observation fails?*

### 1.2 The cold-start defect

Root-caused, fixed, and verified. The durable description:

On cold start with no persisted snapshot, the process publishes a **placeholder**
empty index (`indexed_root: None`, `is_empty: true`,
`load_source: EmptyBootstrap`) and dispatches the real load detached.
`get_file_context` freshens the requested path **before** it consults the loading
guard. The file is absent from the placeholder, so its recorded mtime never
matches disk, so it looks stale and is indexed on the spot — and that mutation
path sets `is_empty = false` while never setting `indexed_root`.

`index_state()` consulted only `is_empty`, so it then returned `Ready`.
`capture_published_manifest` hit its silent `?` on `indexed_root`, so there was no
manifest, no source identity, and the knowledge layer published unbound. The
receipt printed `source=unknown` beside `counts total=0`.

**A file was admitted into the index before the index knew what repository it
was.** Ready without being rooted.

**The fix:** `index_state()` reports `Loading` when `load_source` is
`EmptyBootstrap` — gated on `load_source`, *not* on `indexed_root.is_none()`,
because the P1 local-ref lane (`LiveIndex::from_source_files`) is legitimately
rootless and builds its own source identity via `build_ref_source_generation`. A
root-based guard would pin that lane at `Loading` forever.

**The second-order defect the first fix introduced**, and why the guard has two
conditions: `EmptyBootstrap` covers two lanes. The cold-start lane spawns a
detached reload, so `Loading` is true and transient. The **no-root lane** — the
`else` arm in `main` that calls `set_local_empty_reason` — spawns *neither watcher
nor reload*, so `load_source` can never leave `EmptyBootstrap`. Reporting
`Loading` there tells an agent to retry something that never lands, and hides
`format::empty_index_recovery_hint`, the only message naming the real recovery.
`local_empty_reason` is the discriminator: set exactly in that lane, cleared by
`apply_reload_data`. That lane reports `Empty`.

The first fix traded "reports Ready when it cannot answer" for "reports Loading
when it will never load." Same defect class, opposite direction. Read that twice
before changing this guard.

### 1.3 Why the seam is where it is

An earlier analysis recommended fixing at the admission choke point
(`SharedIndexHandle::update_file`) rather than at `index_state()`. **That
recommendation was wrong, and the reason is worth keeping:** that function has
exactly one real caller (the edit path); the two paths that actually cause this
bug route through `single_file.rs`. Guarding it would have left the reported bug
untouched. The point where writes genuinely converge has no repository root
available, so it could only *refuse* — silently dropping files for embedders with
no error.

One edit at `index_state()` covers all guarded tools, the health readout, and
`status.index_ready` together, because that function owns the decision.

### 2.3 Spec 027 — answer identity disclosure

`specs/027-answer-identity-disclosure/spec.md`. Filed, not implemented.

A code-navigation answer never names the index that produced it, so an answer from
the wrong project is indistinguishable from a fact about the right one.
Reproduced in one call: with the session bound to a worktree lacking
`read_gate.rs`, `search_symbols(query="admit_disk_read")` returned *"No symbols
matching"* — while the symbol sits at `src/protocol/read_gate.rs` in the
repository the operator was working in.

Three properties make it worse than a plain miss: the envelope says
`current index` without saying *which*; the reply suggests `search_text` and
`explore`, steering toward "not a symbol" when the truth is "not that
repository"; and empty results are where disclosure matters most, because a wrong
answer looks wrong under review while a wrong *absence* looks like a fact.

The fix is disclosure on the existing `Source:` axis. **Not** rebinding, **not**
cwd inference — inferring the caller's intent would be the same class of error the
spec exists to remove.

## 3. Binding rules for working in this repo

`CLAUDE.md` is authoritative. The ones that cost real time when ignored:

- **Route every `cargo` build/test/clippy through Terminal Commander**
  `run_and_watch` (argv + cwd + wait_ms, max 60000), resumed with `bucket_wait`
  using bucket_id + cursor. Never sleep-poll. Never `| tail` or redirect-then-grep
  — that discards the result line and captures the wrong exit code. `cargo` locks
  the target dir, so never run two at once.
- **Stage by explicit path.** Never `git add .` / `-A` / `commit -a`. Multiple
  agents and worktrees share this tree.
- **Squash-merge PRs** (`gh pr merge <N> --squash --delete-branch`). The reasons
  are in `CLAUDE.md` and they are load-bearing for release automation.
- **`README.md` and `AGENTS.md` are pinned by a test.** `tests/conformance.rs`
  asserts seven exact phrases across the pair. Grep `tests/` before restructuring
  either. This was learned by breaking CI on `main`.
- **Cite by symbol name, not line number.** New as of this session: line
  citations written into comments were 50+ lines stale *within one edit of being
  written*, because inserting anything above them shifts them. A citation that
  rots on the next insertion is decoration, not evidence.
- **Never hand-write volatile state** (§0 above).

## 4. Gotchas that cost real time

**Two worktrees, one stale.** This repo is commonly checked out twice. One of them
may sit far behind `main` on a feature branch. Reading it will confidently mislead
you — a session nearly filed "that instrumentation doesn't exist" against code
that had been on `main` for weeks. Run the state script; work in the one on
`main` unless you mean otherwise.

**A mis-bound index answers confidently about the wrong tree.** See §2.3. If
`status` shows a `project_root` you did not expect, every empty result you have
seen is void. Every agent carrying SymForge read tools also carries
`index_folder`, which is the recovery.

**Fixture litter trips the detector self-test.** `verify-tools.cjs` runs leave a
SQLite ledger and WAL under `tests/fixtures/verify-tools/.symforge/`. Those are
gitignored and CI never sees them, but locally the WAL can be open when
`repository_source_is_clean_under_its_own_detector` walks the tree, and that test
correctly records an unreadable file as a finding rather than swallowing it —
*unreadable is unverified, never clean*. Delete the litter; do not "fix" the test.

**"I checked them all" needs the same evidence standard as any other claim.** A
verification agent reported four sites as safe having opened three. An external
reviewer opened the fourth and found the hole. There was never a disagreement —
only an incomplete sweep presented as complete.

**A comment is not behaviour. Existence is not invocation.** Three wrong findings
in two days came from citing a doc comment as evidence of runtime behaviour, or
from finding a function that *would* do X without checking anything calls it.

**Work that only exists on one machine does not exist.** Two branches sat
local-only for most of a day — including seventeen commits that existed nowhere
else — while docs were being carefully pushed. Push branches early; a feature
branch does not need a green gate to be safe on the remote, and the PR is where
the gate matters. The same applies to artifacts written outside the repo: a review
packet in a downloads folder is stranded. If a future session should have it, it
belongs in the repo.

## 5. Measurements, with method

Keep the method attached or the number is worthless.

- **Token economics: the published claim was false and is withdrawn.** The README
  claimed 70–95% savings citing a file that does not exist. The one committed
  benchmark measured the *opposite* for the full surface — six correctness-valid
  equivalent scenarios, median sum 4,032 SymForge vs 2,262 baseline (**1.78×
  more**) — and its own verdict was *"do not promote 8.14.0's full surface as a
  safe or token-efficient default without fixes."* See
  `docs/dogfood/2026-07-12-symforge-8.14.0-full-surface-benchmark-report.md`.
  **SFBENCH has not been re-run since.** "The defects were fixed" is not "the
  economics reversed."
- **`rust-cache` was measured slower and reverted.** Details and the untested
  alternatives are in `CLAUDE.md`. Do not re-add the four-key configuration.
- **A parallel-`stat` cold-start optimization was implemented, measured across 3
  samples per side, found 3% *slower* on the cached path, and reverted.** The
  scout is dominated by the directory walk, not the stat.

If a benchmark is re-run, label the corpora honestly: real repositories as
corpora, synthetic scenarios on top. The failure mode last time was presenting
constructed scenarios as "mean ranges from actual test runs."
